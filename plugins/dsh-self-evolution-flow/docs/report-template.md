# 进化报告模板

适用：进化流程第五步。每次进化结束按本模板向用户输出，共三节，不增删章节。

只写结论，不复述工具输出。异常必须附原文片段。

```markdown
## 🧬 进化报告 <YYYY-MM-DD HH:MM>

**1️⃣ 结果**

候选审查：共 X 个。候选区为空时写「0 候选」。

| 候选 | 结论 | 原因 |
|---|---|---|
| <slug> | 启用 / 淘汰 / 并入 | 一句话原因 |

技能变更：
- 新启用：<name>，来源会话，启用后是否确认内容完整
- 更新：<name>，改了什么与为什么
- 归档或淘汰：<name>，依据为使用次数、最后使用时间、失败原因，附用户决策
- 问题与闲置技能须附使用次数与成功/失败/未知计数，让用户一眼看清每个技能的实际表现

记忆与文档：
- 画像文章 `memory/PROFILE.md`：当前 N 字符 / 模型读取时 M 字符；待审草稿写「无」或「有 <id>，差异见 `memory/drafts/<id>/review.md`」；本轮是否成稿待审、是否处置了草稿（采用或丢弃及原因），主题一句话概括
- 收件箱 `memory/inbox/`：待合并 N 份（上限 20），本轮是否手动跑过 `dream`，提取与合并结果；提取只在草稿被采用时才归档
- 技能文档：本轮更新的技能与其改动主题

**2️⃣ 关键动作与系统状态**

| 动作 | 结果 |
|---|---|
| evolve brief | 关键事实，如启用区计数与超长技能 |
| evolve preflight | 硬伤与警示数量 |
| evolve promote / discard | 待审草稿的处置结果与被归档的提取份数 |
| evolve finish | state.json 计数、日志行、git 提交 hash |

- state.json 计数变化：`skillsEnabled`、`skillsUpdated`、`skillsRepaired` 等，写作「前 → 后」
- 记分卡摘要：优秀、健康、未观测、问题、闲置、沉睡、元技能各几个
- 技能总量：当前 X/40
- 本轮 LLM 调用次数与成本

**3️⃣ 待用户决策**

逐项列出，每项写明建议动作与依据。无则写「无」。
```

## 报告纪律

- 报告是给用户的决策材料，不是执行日志。工具输出、文件内容、命令回显都不进报告。
- **正文不超过 1200 字**。写长本身就是耗时来源，超出即视为把执行过程塞进了报告。
- 计数必须来自 `brief`、`health`、`finish` 的实测输出，不凭印象填写。
- 待用户决策一节不得省略。拿不准的判断、涉及删除或压缩的动作、仅有单次证据的画像信息、待审草稿的采用或丢弃决定、与宿主技能同名的冲突都在这里提出。
