# dsh-ui-chat-fold

对话流的三件事，外加轨迹视图里那条没有用处的输入区。套件组件，默认全开，插件页上停用整行即可。

## 自动开合

思考行在模型思考时自己展开、思考一停收回；过程组在过程还跑着时展开、这一段结束收回。

两处都归读者：读者在某个阶段里碰过那一行或那个组，这一阶段内不再动它。让位按阶段算——思考到一半
把行折起来就让它折着，`ok` 到来时该收还是收。

过程组的「收起时机」要是被 dsh 自己设成了「下次发送时收起」，这一段结束后的收起留给官方，组件不抢。

认的语义属性：`data-variant="think"`、`data-state`、`data-expanded`、`data-shimmer`、
`data-step-process`、`data-step-process-body`、`data-group-expanded-mode`。

## 卷帘门

读者点开合控件时，高度逐帧长出来、下方内容真的被推开。收起方向在捕获阶段拦下点击，让真身留在展开态
压到终点再放行——不克隆节点，位移就是文档流本身。

门的行程按「读者看得见的那一段」算，视口外的那一截用剩下的一成时长走完，所以不管展开体是两百像素还是
两万像素，眼前这道门速度一样。主线程卡住的那几帧不算进门的时长。

不参与：弹出层（`aria-haspopup`）、轮次头与轮次触发通知（`data-turn-process`、`data-turn-trigger`）、
dsh 自己正在驱动折叠动效的行（`data-chat-motion`）。自动开合派发的点击不起收起动画。

## 跟随补位

工具行与思考行第一次出现在页面上时，把它们所在的滚动器补到底。靠一条 1 ms 的探针动画拿
`animationstart` 通知，没有观察者、没有定时器、流式期间一个回调都不进。读者自己动过手的滚动器不再补，
直到他回到底部。

## 轨迹视图收起输入区

`[data-conversation-scroll]:has([data-conversation-composer-overlay]) > [data-composer-seat]` 一条
规则：切到「轨迹」页时整条输入区收掉，记录表铺到底。

## 颜色

没有自己的配色，全部沿用 dsh 与套件的令牌；组头标签的流光用 `currentColor`，跟随主题。
