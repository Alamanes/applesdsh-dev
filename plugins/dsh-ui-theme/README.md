# dsh-ui-theme

套件的主题预设与设置页「主题」分区。一套配色换掉整个界面，不只是套件自己的组件。

## 预设

| id | 名称 | 说明 |
| --- | --- | --- |
| `default` | 官方配色 | 不覆盖任何令牌，跟随 DSH 自带的中性灰蓝 |
| `whale` | 鲸海 | 深海的冷蓝，配一张亮白画布 |
| `sakura` | 樱 | 樱粉配梅子夜色 |
| `mint` | 薄荷 | 青绿，干净清透 |
| `dusk` | 暮紫 | 暮色紫罗兰 |
| `amber` | 琥珀 | 暖米金，像灯下的纸 |

每套预设都同时给出浅色与深色两组取值，深浅切换仍由「设置 → 通用 → 外观」控制：主题是
叠在色板之上的一层，不是替换色板。

## 配置

```yaml
- id: dshui-theme
  name: dsh-ui-theme
  config:
    theme: sakura
```

`theme` 是 `volatile` 字段，设置页「主题」分区会直接写它，因此不需要手改 profile。留空或
写一个不认识的 id 都不覆盖任何颜色，界面回到官方配色。

## 实现

- 主题定义是一张「角色 → 令牌」表：每套预设只写画布、三层表面、侧栏/菜单/气泡、墨色梯度、
  一档边框与品牌色，其余（悬停洗色、滚动条、代码块、开关滑块）由这些角色混出来。
- 应用走宿主 ui-theme 包提供的 `ctx.theme` 服务：`overrideTokens(source, tokens)` 把这一层
  叠在活动主题之上，`default` 时移掉该层。服务把令牌发布给 ui-layout 的 presenter，由它写到
  `body` 的内联自定义属性上，所以阅读 `--dsw-*` 的原生控件与阅读 `--dshui-*` 的套件组件一起变色。
- 一个包只占一个覆盖层（source 固定为 `ui-suite-theme`），重复切换是替换而不是堆叠。
- 与鲸鱼壁纸共存：表面类令牌发布成 `var(--dshui-wallpaper-*, var(--dshui-palette-*, <色>))`。
  `--dshui-palette-*` 是本包的主题色，`--dshui-wallpaper-*` 是壁纸包挂载时发布的「同色带 alpha」
  版本。两层谁后注册都解析成同一个结果：壁纸在时按壁纸的透明度透出鲸鱼，壁纸不在时用不透明主题色。
- 选择持久化在本行的 `theme` 配置字段里；下次加载由宿主半边以 `window.DSHUI_THEME` 注入。

## 设置入口

设置面板左侧导航新增「主题」分区（`settings.section`，order 12，排在「通用」与「插件」之间）。
每张卡片是预览缩略图加名称；点一下立刻生效并写回配置，写入被拒时保留当前配色并提示。

## 排错

| 现象 | 检查 |
| --- | --- |
| 导航里没有「主题」 | 本行是否在 boot graph；控制台 `[ui-copy/theme]` 前缀的报错 |
| 切换没反应 | `ctx.theme` 服务是否可用（宿主 ui-theme 包是否启用）；控制台有无 `theme "…" is not registered` |
| 刷新后回到官方配色 | 设置文档是否可写（设置页会提示）；`theme` 字段有没有落到 profile |
| 只有套件组件变色 | 说明只读到了 `--dshui-*`；检查预设是否覆盖了对应 `--dsw-*` 别名 |
