# 候选审查细则

适用：进化流程第二步。候选区非空时阅读本文件。所有动作通过 `evolve` 工具完成，没有 shell 脚本。

## 候选结构

每个候选是 `candidates/` 下的一个子目录，含 `SKILL.md` 与 `meta.md`。`meta.md` 记录来源会话与工具调用、错误次数，是价值判断的主要依据。

## 一、格式校验

先跑机械预检，再做人工复核：

```
evolve action="preflight"                 # 全部候选
evolve action="preflight" slug="<候选名>"  # 单个候选
```

预检完成格式、大小、截断、同名与相似度的机械检查。硬伤必须修复或淘汰，警示项人工判断。预检结果仅供参考，启用决策由人工作出。

校验项：

- frontmatter 含 `name`：小写字母、数字、连字符，长度 1 至 64 字符。
- frontmatter 含 `description`：≤1024 字符，写明了何时使用。
- `SKILL.md` 全文不超过 8000 字符。多个候选同时超限且内容重叠时，先合并压缩到限内再启用，不因超限直接全淘汰。
- 代码围栏是否闭合，被截断的候选文件不得启用。

## 二、查重

与 `skills/` 下已启用技能对比（名称与语义）。预检会给出名称与 description 的相似度警示，并在启用区已有同名技能时直接列为硬伤。语义重复或高度重叠的，合并进现有技能或淘汰，禁止重复启用。

`brief` 还会列出与宿主技能目录（`~/.dsh/skills`、`~/.agents/skills`、项目技能目录）同名的技能。同名会由技能注册表的层内优先级决定谁生效，属于需要用户知情的情况，必须在报告里提出。

## 三、价值评估

至少满足一条才值得启用：

- 这类任务以后会重复出现。
- 步骤明确且可复用。
- 包含真实注意点与解法。

一次性的琐碎问答与闲聊直接淘汰。

## 四、处置

每个候选无论启用、并入还是淘汰，都要记录结论：动作会把 `candidate-verdict` 与一句原因写进 `meta.md` 快照、留档到 `archived/`，并把候选目录出队。候选区不保留已处理目录，否则下次进化会重复审查。

### 启用

```
evolve action="enable" slug="<候选名>" [name="<技能名>"]
```

启用即把候选内容移入 `skills/<name>/`。插件通过技能注册表提供 `skills/` 下的技能，所以启用后立刻对模型可见，无需软链、无需重启。启用后建议读一次 `skills/<name>/SKILL.md` 确认内容完整。

### 并入现有技能

先把候选中有价值的内容合并进目标技能的 `SKILL.md`（更新 description 与正文），再记录：

```
evolve action="merge" slug="<候选名>" target="<目标技能名>" reason="<一句话>"
```

### 淘汰

```
evolve action="reject" slug="<候选名>" reason="<一句话>"
```

质量过差的直接淘汰并记日志。归档与淘汰都只是把技能或候选移出模型可见范围，源文件始终保留。
